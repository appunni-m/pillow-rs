# Fixed in this session (P-mode operations):
# - All 11 P-mode image operation tests now pass. Root cause: Paletted images
#   were converted to RGB before operations, losing P-mode. Fix: Added
#   is_palette_safe_op() to detect ops that work on indices, and materialize()
#   routes them to operate on palette index data directly (matching PIL).
#   Composite/Blend on P-mode also fixed to composite on indices.
# - Image_getpalette_P: Fixed Rust palette extraction in Python bindings and
#   trailing-zero trimming to match PIL's getpalette().
# - All 4 CMYK ImageEnhance tests now pass. Root cause: enhance operations
#   used to_rgb8() which loses CMYK K channel. Fix: Added CMYK-specific paths
#   operating on all 4 channels (C=R, M=G, Y=B, K=A in RGBA8), matching PIL's
#   degenerate computation (C=0,M=0,Y=0,K=255-gray for Color/Contrast on CMYK).
#
# Fixed in this session:
# - ImageDraw_bitmap_1: now passes. Mode-specific fill handling in Rust
#   Draw::bitmap() writes raw byte values for mode "1" (was thresholding to 255).
# - ImageDraw mode-specific text/bitmap: All text() and bitmap() methods now
#   dispatch to mode-specific rendering for modes 1, L, LA, CMYK, P, I, F.
#   Integer fills go to the first channel with others zeroed, matching PIL.
#   Binary modes (1, P, I, F) use coverage > 0 threshold.
#   Anti-aliased modes (L, LA, CMYK) use PIL's BLEND truncation per channel.
# - ImageDraw multiline_text: Now delegates to mode-specific text rendering.
# - Bitmap binding: Changed from per-pixel point() loop to direct bitmap()
#   call, enabling mode-specific handling in the Rust core.
#
# Remaining text/multiline_text failures (ALL blocked by font rendering):
#   PIL's default FreeType font produces slightly different coverage values
#   than fontdue (off by ~4 counts), causing off-by-one blending errors.
#   text_RGBA passes because both PIL and RSPIL use fill=(0,255,0) green,
#   and differences happen to not affect the hash with that input.
#
# Remaining bitmap failures (CMYK, P, F, I — blocked by convert()):
#   RSPIL's Image.convert("1") doesn't threshold properly for these modes,
#   producing grayscale values instead of binary {0,255}. The bitmap mask
#   is created by convert("1"), so incorrect masks cause incorrect output.
#   Fix: Image.convert("1") must threshold at 0 (non-zero → 255) for all modes.
#
# Fixed in previous session:
# - ImageDraw F/I mode support: All 24 F and I mode vector drawing tests
# - ImageFilter.SHARPEN: fixed I mode
# - Image.quantize: fixed L, RGB, RGBA
# - Numerous n-channel mode support fixes
