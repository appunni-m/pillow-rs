# Fixed in this session (PIL-blend formula + rspil_backend alpha fix):
# - Text rendering for L, LA, CMYK modes now passes. Root cause: RSPIL's blend
#   formula used unsigned truncation ((fg*cov + bg*(255-cov))/255) while PIL uses
#   signed rounding (DIV255: (x+127)/255). Fix: Added pil_blend() using PIL's
#   exact BLEND macro: DIV255(dst*(255-mask) + src*mask). This fixed ALL
#   anti-aliased text rendering (L, LA, CMYK) and multiline_text for those modes.
# - rspil_backend._to_rgb_fill() was setting alpha=0 for LA and CMYK mode int
#   fills, which caused render_text() to produce all-zero alpha glyphs and make
#   text invisible. Fix: alpha=255 always; Rust's text_compose_direct handles
#   per-channel zeroing via the is_int_fill heuristic.
# - Multiline_text now passes for L, LA, CMYK, RGB, RGBA (delegates to text).
#
# Remaining text/multiline_text failures (blocked by binary fontmode):
#   PIL uses fontmode="1" for modes "1", "P", "I", "F" — this changes the glyph
#   bitmap to binary (0 or 255) via FreeType's FT_LOAD_TARGET_MONO, producing
#   different glyph shapes than anti-aliased rendering. RSPIL's BitmapFont only
#   stores anti-aliased glyph data. Fix requires separate binary glyph data.
#
# Remaining bitmap failures (CMYK, P, F, I — blocked by convert()):
#   RSPIL's Image.convert("1") doesn't threshold properly for these modes,
#   producing grayscale values instead of binary {0,255}. The bitmap mask
#   is created by convert("1"), so incorrect masks cause incorrect output.
#   Fix: Image.convert("1") must threshold at 0 (non-zero → 255) for all modes.
#
