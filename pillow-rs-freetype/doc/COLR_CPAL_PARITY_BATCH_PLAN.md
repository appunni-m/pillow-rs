# COLR/CPAL parity batch plan

Status: active parity work plan.

Objective: move `ftcolor` rows only when the same font input compares exactly
through pinned C FreeType, Rust FFI, thin C ABI, and WASM ABI. Constants,
missing-font fallbacks, and color-disabled alternate-build assumptions do not
count as runtime color parity.

Current sub-batch: `FT_Palette_Set_Foreground_Color`

- Fixed core Rust FFI behavior for SFNT faces: FreeType 2.14.3
  `src/base/ftcolor.c:95-111` stores `foreground_color` on `TT_Face`, sets the
  validity flag, and returns `FT_Err_Ok`. Rust previously returned
  `FT_Err_Unimplemented_Feature`.
- Routed
  `ftcolor.FT_Palette_Set_Foreground_Color.success_sets_sfnt_foreground_color`
  through pinned C, Rust FFI, thin C ABI, and WASM ABI using the manifest's
  accepted public-color-reference path: select palette 0, set each declared
  foreground color, then observe base glyph 50 through
  `FT_Get_Color_Glyph_Paint` + `FT_Get_Paint` as a PaintSolid color reference
  with palette index `0xFFFF`. This does not claim BGRA render/blend parity.
- Verified non-SFNT no-op and null-face rows still match pinned C, Rust FFI,
  thin C ABI, and WASM ABI exactly. Disabled-color-layer rows still require an
  explicit disabled-color-layer oracle build.

Implemented sub-batch: `FT_Get_Color_Glyph_ClipBox`

- Added maintained compact COLRv1 clipbox fixtures generated by
  `scripts/build_cpal_palette_fixtures.py`:
  - `tests/fixtures/fonts/color/colr-v1-clipbox-format1-format2.ttf`
  - `tests/fixtures/fonts/color/colr-v1-no-clipbox-control.ttf`
- Added pure-Rust COLR v1 ClipList format 1 parsing and
  `FT_Get_Color_Glyph_ClipBox` behavior in core. The implementation follows
  FreeType 2.14.3 `src/base/ftobjs.c` and `src/sfnt/ttcolr.c`: null/no-table/no
  matching glyph returns false without mutating caller output; success scales
  FWORD bounds with active size metrics and applies the active face transform to
  all four public corners before writing `FT_ClipBox`.
- Added thin C ABI and WASM ABI exports that only forward handles/pointers into
  core.
- Routed and verified:
  - `ftcolor.FT_Get_Color_Glyph_ClipBox.clipbox_success_scaled_and_transformed@s12`
  - `ftcolor.FT_Get_Color_Glyph_ClipBox.clipbox_success_scaled_and_transformed@s37`
  - `ftcolor.FT_Get_Color_Glyph_ClipBox.no_clipbox_returns_false_preserves_output`
  - `ftcolor.FT_ClipBox.color_glyph_clipbox_values`
- Current scope intentionally proves the format 1 ClipBox success path. The
  generated fixture also contains a format 2 record as future input, but no
  variable ClipBox row should be credited until a dedicated same-input expected
  output route exercises variation deltas through pinned C, Rust FFI, C ABI, and
  WASM ABI.
