# Contributing to pillow-rs

Thank you for helping improve pillow-rs! This guide covers everything you need to set up, test, benchmark, and contribute.

---

## Dependencies

### Production (what end users install)

`pip install pillow-rs` installs exactly one package. **Zero Python dependencies.**

```bash
pip install pillow-rs   # installs pillow-rs and nothing else
```

- `pyproject.toml` has no `[project.dependencies]` section — pip installs nothing alongside it
- `Image.fromarray()` detects numpy arrays via duck-typing (`hasattr(obj, 'tobytes')`) — no `import numpy` needed
- All image processing happens in compiled Rust — no Python library overhead at runtime

### Development & Testing

Install everything needed for development:

```bash
pip install pillow-rs[dev]
# or individually:
pip install pillow numpy pyyaml pytest pytest-timeout pytest-json-report pytest-benchmark
```

| Package | Used by | Purpose |
|---------|---------|---------|
| `pillow` | tests + benchmarks | PIL reference — every parity test compares RSPIL against Pillow output |
| `pytest` | tests | Test runner |
| `pytest-timeout` | tests | Per-test timeout (300s limit) |
| `pytest-json-report` | tests + coverage | Generates JSON report consumed by coverage scripts |
| `pyyaml` | tests + coverage + benchmarks | Parses `manifest.yaml` |
| `numpy` | tests + benchmarks | Generate array inputs for `Image.fromarray()` parity tests |
| `pytest-benchmark` | benchmarks | Benchmark fixture

### Rust

| Crate | Scope | Purpose |
|-------|-------|---------|
| `criterion` | dev-dependency | Native CPU benchmarks (`cargo bench`). Never in production builds. |
| `wgpu`, `pollster` | production | GPU compute (shaders exist, dispatch stubs not yet wired). |

### System

| Package | Why |
|---------|-----|
| Node.js 20+ | WASM benchmarks only (`scripts/bench/bench_wasm_cpu.mjs`) |
| `fonts-dejavu-core` (Linux) | Benchmark scripts only — the TrueType font bench uses DejaVuSans.ttf |

The core has **zero system dependencies**. It uses `fontdue` (pure-Rust TrueType rasterizer) and a built-in bitmap font for `ImageFont.load_default()`. No system fonts required at build time, test time, or production runtime.

## Build

```bash
# Python — compiles pillow-rs-core + pillow-rs-py (single command)
maturin develop --manifest-path pillow-rs-py/Cargo.toml --release

# WASM — compiles pillow-rs-core + pillow-rs-js (single command)
cd pillow-rs-js && wasm-pack build --target web

# Core tests — compiles and tests pillow-rs-core only
cargo test -p pillow-rs-core
```

`maturin develop` and `wasm-pack build` both compile the entire dependency tree — core gets built automatically. No separate `cargo build` step needed.

The workspace release profile is configured for production:
- `lto = true` — link-time optimization
- `codegen-units = 1` — maximal optimization
- `opt-level = 3` — full optimization (WASM uses `opt-level = "s"` for size)
- `panic = "abort"` — no unwinding overhead

## How to Test

### Full suite (recommended)

```bash
# Build + generate fixtures + run tests
bash scripts/build_and_test.sh

# With a specific suite (suite0 = default, suite1/2/3 = larger fixtures)
bash scripts/build_and_test.sh 1
```

This script:
1. Builds pillow-rs (`maturin develop --release`)
2. Generates test fixtures from manifest (`scripts/generate_fixtures.py`)
3. Runs `pytest tests/test_parity.py --timeout=300`
4. By default runs only `suite0` (fast, core coverage). Use suite arg for extended fixtures.

### Direct pytest

```bash
# All suites (1,555 tests — takes ~60s)
python -m pytest tests/ -q --tb=line --timeout=300

# Single failing test
python -m pytest tests/ -k "test_name" -v --tb=long --timeout=300

# With JSON report for coverage
python -m pytest tests/ --json-report --json-report-file=/tmp/report.json -q --timeout=300
```

### Core Rust tests

```bash
cargo test -p pillow-rs-core
```

### Test architecture

Tests live in `tests/test_parity.py` and are parametrized from `manifest.yaml`. Each test:
1. Creates identical inputs for both **PIL** (reference) and **RSPIL** (pillow-rs)
2. Runs the same operation on both
3. Asserts binary-identical output using `assert_images_equal()` or `assert_values_equal()`

Test fixtures are generated by `scripts/generate_fixtures.py` into `tests/fixtures/outputs/`. Fixtures are NOT committed — they're regenerated before each run.

## How to Check Coverage

```bash
# 1. Run tests with JSON report
python -m pytest tests/ --json-report --json-report-file=/tmp/report.json -q --timeout=300

# 2. Compute coverage against manifest
python scripts/coverage/compute_coverage.py manifest.yaml /tmp/report.json

# 3. Generate coverage docs
python scripts/coverage/generate_multi_backend_coverage.py  # → docs/COVERAGE.md
python scripts/coverage/generate_wasm_coverage.py           # → docs/COVERAGE_WASM.md
```

Coverage mapping lives in `scripts/coverage/coverage_map.json`. Every test function must be mapped to its manifest function(s). When you add a new test, add its entry to this file.

The CI gate (`scripts/ci_coverage.sh`) runs the full pipeline and fails on any coverage gap.

## How to Benchmark

### Quick: full suite

```bash
bash scripts/bench/bench_all.sh full
```

This runs all 166 functions across all available targets and regenerates `BENCHMARKS.md`.

### Incremental (only changed code)

```bash
bash scripts/bench/bench_all.sh incremental
```

Uses SHA-256 cache keys — unchanged functions skip re-benchmarking.

### Targeted

```bash
# Priority tier (12 most-used ops)
bash scripts/bench/bench_all.sh --group priority

# Specific functions
bash scripts/bench/bench_all.sh --only resize,crop

# Single target
bash scripts/bench/bench_all.sh --target native_cpu
```

### Benchmark architecture

| Script | Role |
|--------|------|
| `bench_all.sh` | Entry point — orchestrates the pipeline |
| `bench_spec.py` | Reads `manifest.yaml` → generates `bench_spec.json` (which functions to bench) |
| `bench_pillow_baseline.py` | Runs Pillow on each function to establish baseline timings |
| `bench_native_cpu.py` | Runs pillow-rs native CPU, compares to Pillow baseline |
| `bench_wasm_cpu.mjs` | Runs pillow-rs WASM in Node.js |
| `bench_browser.mjs` | Runs pillow-rs WASM in headless Chrome (puppeteer) |
| `bench_aggregate.py` | Collects all JSON outputs → generates `BENCHMARKS.md` |
| `bench_cache.py` | SHA-256 cache for incremental runs |

### Adding a new function to benchmarks

The benchmark spec is auto-generated from `manifest.yaml`. If the function has `supported_targets: [cpu]`, it's automatically included. No manual benchmark registration needed.

## Manifest-Driven Development

All work starts from `manifest.yaml` — the single source of truth for the API surface.

### Adding a new function

1. **Define** — Add the function entry to `manifest.yaml` (name, signature, modes, variants, edge cases, `supported_targets`)
2. **Generate stubs** — `python scripts/generate_stubs.py` scaffolds Rust stubs in core
3. **Implement** — Fill in the stub in `pillow-rs-core/src/ops/<module>.rs`
4. **Add binding** — Add `#[pyfunction]` delegation in `pillow-rs-py/src/lib.rs`
5. **Add Python wrapper** — Thin wrapper in `pillow-rs-py/python/pillow_rs/` (NO loops, NO arithmetic, NO math imports — pure delegation to `_core.xxx()`)
6. **Register module** — If new module: add to `pillow-rs-py/python/pillow_rs/__init__.py` and `pillow-rs-core/src/ops/mod.rs`
7. **Write tests** — PIL parity test in `tests/` using `assert_images_equal()` or `assert_values_equal()`
8. **Add fixture** — JSON fixture in `tests/fixtures/` with `operation.module` + `operation.target`
9. **Map coverage** — Add entry to `scripts/coverage/coverage_map.json`
10. **Verify** — `python scripts/coverage/compute_coverage.py manifest.yaml /tmp/report.json`

### Fixing a failing parity test

1. Identify the failing test from `xfailed_tracker.txt` or pytest output
2. Run it in isolation: `python -m pytest tests/ -k "test_name" -v --tb=long`
3. Compare RSPIL output vs Pillow output to understand the gap
4. Fix the Rust implementation in `pillow-rs-core/src/ops/`
5. Re-run to confirm it passes
6. Run full suite to check for regressions

## Architecture Rules

**Iron rule:** `pillow-rs-core/` never touches Python objects, JS objects, file paths, or network.

| Layer | Can do | Cannot do |
|-------|--------|-----------|
| `pillow-rs-core` | Image processing, math, algorithms, color conversion | Python/JS objects, I/O, file paths, network |
| `pillow-rs-py` | PyO3 type conversion, file open/read/save | Loops, arithmetic, image logic, math |
| `pillow-rs-js` | wasm-bindgen, JS typed arrays, browser APIs | Loops, arithmetic, image logic, math |

**Python binding rules** — files in `pillow-rs-py/python/pillow_rs/`:
- ❌ NO `for`/`while` loops
- ❌ NO list comprehensions
- ❌ NO `import math`, `import tempfile`, `import os`, `import subprocess`
- ❌ NO arithmetic (`+`, `-`, `*`, `/`, `min`, `max`, `sorted`, `sum`)
- ❌ NO `if`/`elif`/`else` beyond `isinstance` checks, `None` defaults, or mode dispatch
- ✅ Every method delegates to `_core.xxx()` or `_rust_image.xxx()`

## Drawing Architecture — Per-Mode Native Paths

Drawing functions (`line`, `rectangle`, `ellipse`, `polygon`, `arc`, `point`, `bitmap`, `text`) dispatch on canvas color type and draw directly in the native pixel format. **Zero lossy conversions.**

```rust
// Instead of converting everything to RGBA:
// let canvas = img.to_rgba8();  // ❌ lossy for L, F, I, CMYK

// Each mode gets its own pixel write path:
match canvas {
    Luma8(_)  => draw with 1-byte pixel writes,
    LumaA8(_) => draw with 2-byte pixel writes,
    Rgb8(_)   => draw with 3-byte pixel writes,
    Rgba8(_)  => draw with 4-byte pixel writes + alpha,
    _ => fallback with explicit_mode tracking,
}
```

## Code Style

### Rust

```bash
# Format
cargo fmt

# Lint (must pass with zero warnings)
cargo clippy --all-targets --all-features -- -D warnings
```

Pre-commit checklist:
- [ ] No `unwrap()` or `expect()` outside `#[cfg(test)]`
- [ ] `thiserror` for error types, never bare `anyhow` in core
- [ ] `&str` over `String`, `&[T]` over `Vec<T>` in function parameters
- [ ] `#[derive(Debug)]` on all public types
- [ ] `///` doc comments with `# Examples` on all `pub` functions
- [ ] Import order: `std` → external crates → `crate` → `super` → `self`
- [ ] No redundant `.clone()` — prefer borrowing

### Naming

- **Public API names match Pillow exactly** — `Image.open()`, `Image.resize()`, etc.
- **Import name** is `RSPIL` (mirrors `PIL`)
- **Internal Rust types** can use any naming convention

## Commit Guidelines

- Work on feature branches, never commit directly to `main`
- Run `cargo fmt` and `cargo clippy --all-targets --all-features -- -D warnings` before committing
- Run the full test suite and check for regressions
- Commit messages describe what changed and why
